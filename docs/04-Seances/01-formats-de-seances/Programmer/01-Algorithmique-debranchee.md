# 🧩 Algorithmique débranchée

> *« Avant de programmer un ordinateur, il faut apprendre à organiser sa pensée. »*

---

# Principe

Les élèves découvrent les notions fondamentales de l'algorithmique sans utiliser d'ordinateur.

Ils manipulent, expérimentent et coopèrent pour construire des suites d'instructions permettant d'atteindre un objectif.

Ils découvrent progressivement que programmer consiste avant tout à :

- décomposer un problème ;
- organiser des actions ;
- prévoir le résultat ;
- tester ;
- corriger.

---

# Pourquoi utiliser ce format ?

Beaucoup d'élèves pensent que programmer consiste à utiliser un logiciel.

Au Math'Lab, ils découvrent que la programmation est avant tout une démarche de raisonnement.

L'ordinateur devient un outil… mais la réflexion reste humaine.

---

# Objectifs

Les élèves apprennent à :

- écrire une suite d'instructions ;
- respecter un ordre logique ;
- anticiper les conséquences d'une action ;
- identifier une erreur ;
- améliorer un algorithme.

# Les notions abordées

Selon les activités, les élèves découvrent :

- la notion d'algorithme ;
- les instructions ;
- les séquences ;
- les répétitions ;
- les conditions (« si… alors… ») ;
- les tests ;
- le débogage.

Le vocabulaire est introduit progressivement et toujours à partir de situations concrètes.

# Déroulement type

## 1. Comprendre le défi (5 min)

Présentation de la mission.

Les élèves identifient :

- le point de départ ;
- l'objectif ;
- les contraintes.

---

## 2. Construire un premier algorithme (10 min)

Les élèves proposent une suite d'instructions.

Ils peuvent utiliser :

- des cartes ;
- des flèches ;
- des pictogrammes ;
- un langage naturel.

---

## 3. Tester (10 à 15 min)

L'algorithme est exécuté.

Par exemple :

- un élève joue le rôle du robot ;
- une équipe suit les instructions ;
- un déplacement est réalisé sur quadrillage.

Les erreurs sont observées.

---

## 4. Déboguer (10 à 15 min)

Les élèves corrigent leur algorithme.

Ils cherchent :

- l'instruction incorrecte ;
- l'ordre des actions ;
- les oublis.

Ils testent de nouveau.

---

## 5. Prendre du recul (5 min)

Discussion collective :

- Qu'est-ce qui a fonctionné ?
- Pourquoi le programme s'est-il trompé ?
- Comment l'améliorer ?

# Différenciation

## Pour aider

- réduire le nombre d'étapes ;
- proposer des cartes d'instructions ;
- utiliser des déplacements simples.

---

## Pour aller plus loin

- introduire des boucles ;
- utiliser des conditions ;
- optimiser l'algorithme ;
- écrire plusieurs solutions.

# Variantes possibles

## 🤖 Robot humain

Un élève exécute exactement les consignes données par son équipe.

---

## 🧩 Labyrinthe

Créer un algorithme pour sortir d'un labyrinthe.

---

## 🍳 Recette

Écrire un algorithme permettant de réaliser une tâche du quotidien.

---

## 📐 Géométrie

Décrire la construction d'une figure comme une suite d'instructions.

---

## 🎨 Pixel Art

Créer ou reproduire une image à l'aide d'un algorithme.

---

## 🧱 Défi de construction

Programmer les étapes permettant de construire une figure ou un assemblage.

---

# Erreurs fréquentes

Les élèves peuvent :

- oublier une instruction ;
- inverser deux étapes ;
- utiliser des consignes ambiguës ;
- ne pas tester leur algorithme.

Le rappel essentiel :

> Un programme faux n'est pas un échec. C'est une occasion de comprendre pourquoi il ne fonctionne pas.

---

# Conseils de mise en œuvre

Les activités doivent rester très concrètes.

Les élèves manipulent avant de formaliser.

Le passage vers Scratch ne se fait que lorsque les principes fondamentaux sont compris.

# Place dans le Math'Lab

L'algorithmique débranchée montre que programmer ne commence pas devant un écran.

Elle apprend aux élèves à organiser leur pensée, à tester leurs idées et à améliorer progressivement leurs solutions.

> **Avant d'apprendre à programmer une machine, les élèves apprennent à programmer leur raisonnement.**
